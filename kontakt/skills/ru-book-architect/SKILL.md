# Архитектор книжного проекта
## Язык и общий модуль

Новая художественная проза — украинская (`uk`); новый английский оригинал возможен по явному выбору. Русские файлы сохраняются как legacy-источники. Исторический ID `ru-` совместим с новым процессом и не предписывает русский язык. Прочитать `project.json.book_system`: `CORE.md`, целевой `LANGUAGES/uk/STYLE.md` или `LANGUAGES/en/STYLE.md` и относящийся рабочий процесс. Для готового RU-текста и его переноса использовать `ADAPTATION/WORKFLOW.md`; языковая смена не разрешает сюжетную редактуру. Завершение литературного цикла включает Opus, Gemini 3.8 Flash и Gemini 3.1 Pro по `REVIEW.md`.


1. Определить книгу, стадию и результат из запроса. Продолжать уже разрешённую работу. Назначенный автором окончательный файл имеет приоритет перед форматом, датой изменения и количеством исправлений в других версиях.
2. Составить инвентаризацию: файл, фактический формат, проект/том, роль, основание статуса, полнота. Различать рукопись, замысел, шаблон с примерами, извлечение и отзыв. Не переносить канон соседнего проекта. Текстовая копия с расширением DOCX не является исходным Word-файлом.
3. Прочитать [схему](references/project-schema.md). Создавать только нужные для текущей стадии документы. Взять [манифест](assets/project-manifest.json) как заготовку; неизвестные поля оставить null.
4. Для новой книги определить читательское обещание, внешнюю цель героя, внутреннее противоречие, противодействие, цену выбора и развязку тома. Затем построить причинную последовательность сцен и карту раскрытий. Применять Труби, Воглера и Save the Cat как линзы, без обязательных квот и процентов.
5. Для готовой книги восстановить события из текста. Запись «аудит пройден» в справочнике не заменяет проверки. При конфликте показывать «в тексте» и «в плане»; не переписывать рукопись под устаревший план автоматически.
6. Отделять канон серии, состояние на конец каждого тома и замысел продолжений. Различать истину мира, знание героев и знание читателя.
7. Описать голос по образцам: защищаемые черты, диапазон голосов персонажей, риски. Не включать личную биографию автора в переносимый профиль. Частота приёма сама по себе не является запретом.
8. Выдать конкретную структуру, назначение файлов, порядок обновления и критерии завершения. Для полного аудита применить ru-book-auditor, для отзывов — ru-book-revision, если доступны; иначе выполнить работу явно, без заявления об их запуске.
9. Сохранить пользовательские артефакты постоянно. Для Word применять documents, для установки скиллов — skill-creator. Не менять выбранный мастер ради удобства инструментов.

Завершение: один назначенный мастер, изолированные книги, отделённые планы/факты, минимальная схема и маршрут от замысла до выпуска. Не обещать автоматическую объективную оценку литературы. Честно обозначать непрочитанное и невыполненное.
