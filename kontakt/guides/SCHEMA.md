# Схемы и пути

В этой сборке project.json — манифест проекта; books/ID/book.json — манифест книги. Общие обозначения project/manifest и book-01/plan из скиллов означают те же логические роли, переименовывать файлы не нужно.

Мастер хранит path относительно папки книги, format (docx/text), sha256, status (author_selected/candidate) и authority — основание выбора. У новой книги master=null. Производные записи связываются с исходником по source_sha256; якорь включает главу, абзац и точную цитату. После смены хеша номера абзацев перепроверяются.

JSON-реестры содержат описание fields и пустой items. Поля помогают человеку и ИИ заполнять данные; это не формальная JSON Schema. doctor проверяет только явно описанные в tools/README.md структурные условия, а не литературную полноту записей.

| Файл книги | Содержание |
|---|---|
| scenes.json | Цель, препятствие, решение, цена и переход |
| characters.json | Желание, потребность, противоречие, выбор, голос |
| knowledge.json | Кто узнал что, когда, откуда; догадка отдельно |
| timeline.json | Начало, длительность, дорога, общий дедлайн и местное окно |
| resources.json | Было, пришло, ушло, осталось; единицы и вложенные группы |
| promises.json | Обещание, подготовка, ложное прочтение, раскрытие, отдача |
| motifs.json | Повтор, новая функция, изменение значения, решение |
| audit/issues.json | Наблюдение, эффект, доказательства, приоритет и правка |
| end-state.json | Что подтверждено в фактическом финале |

Статус факта: planned/observed/confirmed/disputed/retired. Состояние замечания: proposed/accepted/rejected/applied/verified. Применённая правка ещё не означает проверенную. severity: critical/major/minor/optional. certainty: text_conflict/missing_link/interpretation/preference.

doctor не вычисляет знания героев, полноту драматургии и истинность канона. Такие записи сверяет читатель или профильный аудит с источником. Не заполняйте пустые формы выдуманными «проверенными» фактами.
