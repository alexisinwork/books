# Инструменты и проверяемые границы

Python 3.10+, стандартная библиотека; команды ниже выполняются из корня мастерской. Они не вызывают модели, не тратят API-кредиты и не переводят прозу. Новый путь вывода обязателен: существующие пакеты и зафиксированные отчёты не перезаписываются.

## Новые книги

`studio.py new-book --root PROJECT --id ID --title TITLE --profile custom` создаёт украинский оригинал по умолчанию. `--language en` явно выбирает английский оригинал. `set-master --language` описывает фактический язык выбранного файла, не переводит его.

`new-project` запускается из чистого `default`. Он копирует ядро в локальный `book-system`, помощники в `tools`, три новых навыка в `.agents/skills` и фиксирует происхождение ядра/помощников в `SYSTEM-SNAPSHOT.json`. Чужие книги, канон, подключения и реестр старых изданий не наследуются. В самостоятельном проекте путь ядра следует `project.json.book_system`; общий root для команд адаптации можно задать как родитель проекта через `--root`, а `--project` — имя каталога.

## Подготовка адаптации

1. `literary_translation.py inventory` инвентаризует только зарегистрированные мастера, проверяет их хеши и сохраняет снимки метаданных. Рабочие редакции перечисляет, но не назначает источником. Книги без мастера пропускает. Для настоящей адаптации окончательный исходник сначала выбирается автором и архивируется с точным SHA; его версия не подменяется более свежим кандидатом.
2. `annotate-glossary` ищет заранее предложенные термины и сохраняет цитаты/позиции. Поиск по словарю не равен полному извлечению всех имён и смыслов.
3. `prepare_language_editions.py` создаёт семь постоянных документов и журналы для UK и EN, без текста романа. EN остаётся `awaiting_UA_CANONICAL_MASTER`. Это подготовитель legacy-маршрута, не средство назначить мастер.
4. `literary_translation.py prepare` собирает русские либо украинские исходные главы и привязывает каждый подключённый файл правил к хешу. Глава 0 означает текст до первого заголовка или весь рассказ без глав. Обход сложных DOCX-структур запрещён без отдельного плана извлечения.

Пример проверки уже подготовленной Риокки:

```bash
python3 tools/literary_translation.py verify-preparation --package riokka/translation/preparation-2026-09-14
```

Для следующего пакета (точный набор `--input` определяется сценой):

```bash
python3 tools/literary_translation.py prepare --inventory SOURCES_JSON --book book-01 --chapters 4 --target-language uk --input AUTHOR_INTENT_MD --input STYLE_GUIDE_MD --input GLOSSARY_JSON --input MEANING_LEDGER_JSON --out NEW_PACKET
```

`prepare` принимает только основу с авторским статусом. Это не подтверждение готовности всех решений к переводу. Утверждённые glossary/ledger/intent должны быть актуальны; сменившийся хеш входа делает старый пакет непригодным для нового прохода. Ранее принятые решения и отчёты сохраняются как история, а не чинятся под новый хеш.

## Когда перевод будет отдельно поручен

Адаптер создаёт `translation.json` по [схеме](ADAPTATION/SCHEMA.md). В нём нет свободно потерянных абзацев: каждому исходному ID соответствует блок; разделение/объединение допускается с причиной. Чистый целевой текст собирается из блоков.

```bash
python3 tools/literary_translation.py check --packet PACKET --translation TRANSLATION_JSON --glossary GLOSSARY_JSON
python3 tools/language_qa.py --language uk --source TARGET_TEXT
python3 tools/literary_translation.py freeze --packet PACKET --translation TRANSLATION_JSON --glossary GLOSSARY_JSON --out NEW_RUN --model ACTUAL_MODEL --client ACTUAL_CLIENT
python3 tools/literary_translation.py blind-pack --run RUN --prompt BOOK_SYSTEM/ADAPTATION/prompts/target-only-uk.md
```

Для EN: `--target-language en`, `language_qa --language en`, `target-only-en.md`; остальные проверки зеркальны. У UK→EN источник обязан иметь язык `uk` и утверждённую каноническую роль по решению автора. RU→EN — только отдельный явно выбранный маршрут.

Слепой пакет создаётся вне репозитория: целевой текст, нейтральная инструкция, форма отчёта. Читатель запускается в новой сессии без остальных материалов. Отчёт содержит `Status: final` и `Target SHA-256: ...`.

```bash
python3 tools/literary_translation.py record --run RUN --role gemini_pro --report REPORT_MD --model ACTUAL_MODEL --client ACTUAL_CLIENT
python3 tools/literary_translation.py verify-run --run RUN
```

Роли адаптации: `bilingual`, `opus`, `gemini_flash`, `gemini_pro`, затем `reconciliation`; `human` отдельно. Сведение нельзя зафиксировать без первых четырёх отчётов. Фиксация сохраняет отчёт, но сама по себе не доказывает независимость модели и не утверждает книгу. Авторские решения ведутся в реестре издания; публикационный допуск — по WORKFLOW/VERSIONS, автоматического `promote` здесь нет.

## Что проверяет механика

SHA источника, входных правил и отчётов; точное извлечение выбранных единиц; пропуски ID, дубли и порядок; границы глав; непустой целевой текст; locked-термины и перечисленные допустимые формы. Предлагаемые термины дают незакрытый вопрос, а не обязательную замену. Числа и соотношение длины — сигналы для чтения; запись чисел словами/другой десятичный разделитель требуют человека или смыслового reviewer.

Механика не проверяет полноту смысла внутри абзаца, реальную сохранность ledger, юмор, подтекст, грамматику целиком или удовольствие читателя. Эти пункты проверяются и перечисляются в независимых отчётах. Украинские кальки и чужие буквы — контекстные сигналы, не повод для глобальной замены. В английском выводе кириллица блокирует текущий технический профиль; намеренная цитата на другом языке требует отдельного зафиксированного исключения/профиля до выпуска, а не удаления нужного смысла.

Проверки разработки: `python3 -m unittest discover -s tests -v`; для каждого проекта — `python3 -m unittest discover -s PROJECT/tests -v` и `python3 PROJECT/tools/studio.py doctor --root PROJECT`. Хеши не сертификат художественного качества.
