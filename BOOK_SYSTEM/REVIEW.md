# Независимая литературная проверка

По последнему поручению автора новые прогоны ансамблевой схемы 2 включают четыре диагноза: **Astra, Claude Opus, Gemini 3.8 Flash и Gemini 3.1 Pro**. В обычном цикле, где пишет Sol, все четыре прохода независимы. Эти роли обязательны; прежняя рекомендация делать Pro необязательным отменена. Подготовка системы не означает, что эти модели уже читали роман.

Постоянный выбор клиента: Gemini — **только `agy CLI`**, никогда `gemini CLI`; обязательный Opus — **Claude Code**. Сначала проверить доступные в `agy` идентификаторы моделей; записать запрошенный и фактически возвращённый идентификатор, клиент и хеш пакета. При недоступности `agy`/модели отметить `unavailable`, без скрытого fallback и без выдачи своей проверки за Gemini. Исторические журналы старых клиентов не переписывать.

| Роль | Задача | Контекст |
|---|---|---|
| Opus | Сцены, украинская/английская проза, различимость голосов, эмоция и минимальные исправления | Выбранный текст, правила и относящийся канон; для адаптации также исходник и ledger |
| Gemini 3.8 Flash | Полное покрытие, повторяющиеся выражения, голоса, связи, callbacks и глоссарий; каждый вывод подкрепить якорями | Тот же фиксированный текст; для смысловой сверки исходник; без отчётов остальных |
| Gemini 3.1 Pro | Холодное чтение и литературная связность на целевом языке | Изолированный целевой текст, нейтральная форма отчёта; без исходника, канона, intent, глоссария и подсказок |
| Astra | Архитектура, периодический аудит 4–6 глав, сложные конфликты, сведение | На независимом проходе — без чужих отчётов; при сведении — только после их фиксации |

Для перевода один основной адаптер выбирается по анонимной пробе Sol/Opus. Если выбран Opus, независимую двуязычную сверку выполняет Sol; обязательный литературный проход Opus фиксируется как авторский/self-review, а не независимый. Astra, Gemini Flash и Pro остаются независимыми. В manifest этот Opus получает `review_relationship: "self_review"`, а для внешнего зафиксированного target указывается `target_producer_model`; через `from_job` производитель устанавливается по предшественнику. Сведение требует также пятый отчёт `bilingual` от Sol и сохраняет различие между самооценкой и независимыми диагнозами. Один фактический исполнитель не обозначается двумя независимыми моделями.

Модель не назначает канон и не утверждает варианты большинством. Замечания: S1 — факт/причина/тайна/характер/значимое предвосхищение; S2 — юмор/подтекст/голос/эмоция/образ; S3 — язык/калька/регистр/термин; S4 — необязательный вкус. Уверенность хранится отдельно от серьёзности.

Нет выполненного отчёта — `not_run`, недоступна модель — `unavailable`, изменился источник — `stale`. Нельзя заменить отсутствующий обязательный проход своей имитацией и назвать цикл завершённым. Можно продолжать независимую подготовку и черновую работу; готовность к выпуску остаётся открытой.

После правок холодное чтение получает новый контекст. Формальное наличие длинного окна не удостоверяет чтение всех глав: в отчёте обязательны карта покрытия, точные места, конец прочитанного объёма и список пропущенного.

Запуск и продолжение ведёт координатор по [ORCHESTRATION](ORCHESTRATION.md): Astra → Sol → фиксация текста и SHA → параллельные независимые диагнозы → проверка координатором → сведение → порученные исправления → новый прогон. Очередь допускает сведение только после принятия всех четырёх результатов одного `review_set` с одним target SHA. `accept` удостоверяет пригодность конкретного артефакта как входа следующего задания после его чтения; он не заменяет авторское решение по замечаниям. Координатор выполняет это действие и возобновляет очередь самостоятельно в рамках уже порученной работы.

Для agy общий stdin-пакет ограничен 120 000 UTF-8 байт. Слишком большой текст делится на цельные блоки с отдельными хешами и общей картой покрытия; проверки межглавных связей планируются отдельно. Нельзя обходить границу через file mode, отключение разрешений или другой клиент. Отсутствие инструментальных событий и временная рабочая папка не удостоверяют строгую изоляцию файловой системы. Реальные входы, клиентские свидетельства и ограничения независимости проверяются перед `accept`.

Старые ансамблевые прогоны схемы 1 сохраняют свой исторический состав. Новые прогоны схемы 2 добавляют обязательный `gemini_flash`; ключ `gemini` означает Pro. Обновление правил не изменяет зафиксированные старые отчёты.
