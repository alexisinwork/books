# Google Drive и GitHub

## Одна структура файлов

Общий репозиторий содержит `default/`, `buro/`, `kontakt/`, `riokka/`. У каждой серии свой `project.json`, `series/`, `skills/`, `tools/` и `books/`; у каждого тома отдельная рабочая папка. `default/` остаётся чистым образцом для новых миров. Для нового тома не копируйте целую серию: выполните new-book внутри неё.

Git хранит историю изменений и варианты в ветках. Markdown, JSON и текстовые проекции можно сравнивать по строкам. DOCX хранится исходным файлом, а `derived/manuscript.txt` показывает изменения текста. Эта проекция не доказывает сохранность оформления. [Об устройстве Git](https://docs.github.com/en/get-started/using-git/about-git).

## Ежедневная работа

Обновите локальную ветку, выберите папку серии и книгу. После осмысленной правки назначьте новую версию мастера, обновите snapshot и затронутые доказательства. Прочитайте diff и выполните doctor. Коммит должен описывать выполненное изменение: «Уточнена причина решения в главе 4», например. Альтернативную сцену сохраняйте в ветке либо в archive с явным статусом; действующий мастер у книги один.

Репозиторий с неопубликованными произведениями используйте как приватный. Для отдельного общедоступного шаблона копируйте только default после проверки исторических материалов и прав. Весь репозиторий не назначайте шаблоном: копия унаследует рукописи. GitHub template repository создаёт новую историю. [Создание из шаблона](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template).

После клонирования существующего репозитория повторно создавать его не нужно. Если размещаете новую локальную копию впервые, выполните из её общего корня после входа в GitHub CLI:

```sh
git init -b main
git add .
git commit -m "Initial writing workspace"
gh repo create book-writing-studio --private --source=. --remote=origin --push
```

[Параметры gh repo create](https://cli.github.com/manual/gh_repo_create). Эти команды являются инструкцией; фактический адрес созданного репозитория сообщается отдельно и записывается при подключении. Файл с командами не подтверждает внешнюю запись.

## Google Drive

В Drive сохраняйте ту же иерархию четырёх обычных папок и отдельные читательские файлы. При первоначальной загрузке используйте «Создать → Загрузить папку». [Загрузка файлов и папок](https://support.google.com/drive/answer/2424368?co=GENIE.Platform%3DDesktop&hl=en). Для новой серии сначала создайте локальную папку командой new-project, затем загрузите её.

Если редактируете Google Docs, перед аудитом экспортируйте конкретную версию в DOCX, запишите ссылку и дату экспорта и назначьте полученный файл мастером. Проверка относится к этому снимку. Выгрузка не делает старый Markdown окончательным текстом автоматически.

Рабочую папку Git держите отдельно от автоматического зеркала Drive. Переносите законченные изменения и выпуски, чтобы два сервиса не перезаписывали один открытый файл. Для автоматизации подходит осознанное копирование после пробного запуска; rclone copy не удаляет лишние файлы назначения. [Поведение copy](https://rclone.org/commands/rclone_copy/).

## Собрать новую общую рабочую папку

Существующие четыре папки уже готовы к использованию. Дополнительная команда нужна только для их переноса в новую, ещё не существующую общую папку:

```sh
python default/tools/prepare_repository.py --default default --buro buro --kontakt kontakt --riokka riokka --out ../book-writing-studio-copy
```

Команда копирует исходные байты, добавляет общий workflow проверки и не выполняет сетевых действий. Канон и настройки серий не меняются. Для ежедневного продолжения работы повторная сборка не требуется.
