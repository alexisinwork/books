# Применение решений автора

1. Прочитайте общий и проектный `AGENTS.md`, `project.json`, `START_HERE.md`, `book.json`, `run.json`, `author-decisions.md` и `issue-ledger.json`. Выполните `python3 tools/editorial_ensemble.py verify --run PATH`; этап решений должен иметь статус `locked`.
2. Прочитайте `skills/ru-book-revision/SKILL.md` выбранного проекта и один специфический навык серии, если он существует. Для каждой сцены выполните обязательный цикл `guides/SCENE-EDITING.md`.
3. Составьте совместимый пакет только из пунктов `accepted` и `modified`. `rejected` не применяйте; `deferred` оставьте открытым с указанными зависимостями. Если два принятых решения конфликтуют, зафиксируйте конфликт и продолжите независимые пункты.
4. Сохраните предыдущую версию и SHA-256. Меняйте порученную рабочую редакцию или мастер согласно явному статусу; не переписывайте `sources/originals` и не повышайте кандидат до мастера по собственной инициативе.
5. После каждой затронутой сцены обновите события, время, ресурсы, знания, обещания, канон только при авторском основании, производные тексты, точные якоря, журнал и «Было — стало». В `issue-ledger.json` запишите пути и состояние применения.
6. Перечитайте зависимые сцены. Запустите проверки прозы, LanguageTool/Vale при доступности, проверки проекта, хешей и итогового документа. Для DOCX сравните извлечение и осмотрите рендер.
7. Заполните `verification.md` фактическими командами, охватом, хешами, результатами и остаточными вопросами. Удалите `<!-- FILL -->`, поставьте `Status: final`, обновите проверки каждого пункта и выполните `python3 tools/editorial_ensemble.py record --run PATH --role verification`.

После изменения текста новый холодный читательский эксперимент всегда получает новый `run-id` и новый пакет без списка внесённых правок.
