# Единое хранилище книг

Рабочее хранилище — [alexisinwork/books](https://github.com/alexisinwork/books), ветка `main`. Текущая локальная рабочая копия находится в WSL: `/home/alexi/books`. Windows-папка `C:\Users\alexi\Desktop\writing-studio` была источником первоначального импорта; дальнейшие изменения рабочего репозитория не синхронизируются с ней автоматически.

## Что является источником правды

| Объект | Где определяется действующая версия |
|---|---|
| Общий состав проектов и история | Этот Git-репозиторий: `default/`, `buro/`, `kontakt/`, `riokka/`. |
| Основной текст конкретной книги | `books/ID/book.json.master`: путь, SHA-256 и основание выбора автора. Для первой книги Риокки выбран DOCX. |
| Отдельная новая редакция | `book.json.working_revision`, её текст, состояния и журнал в `revisions/`. Она не становится принятой только из-за более новой даты. |
| Неизменяемый исходник | `sources/originals/` и манифест его происхождения/хеша. |
| Канон и состояние сцены | Канон по ссылке в `book.json`, `characters.json`, `knowledge.json`, `timeline.json` и остальные реестры с привязкой к версии и доказательствам. |
| Поисковый текст, статистика, проверки | Производные файлы и отчёты с указанием исходного пути, хеша, инструмента и охвата. |
| Новое редакторское решение | Явный статус и основание в замечаниях/журнале. Неразрешённый вопрос остаётся `unresolved`. |

[Риокка-1: оригинал, последняя редакция и «было → стало»](riokka/books/book-01/README.md). Эти роли уже записаны в её манифесте; эта схема не меняет выбранный автором мастер.

При добавлении или выборе новой редакции обновите также README книги и ссылки в указателях мастерской. Актуальный путь и статус берите из `book.json`; хеши и даты в обзорных страницах описывают явно указанный снимок.

## Работа из Windows и WSL

Используйте одну рабочую копию либо отдельные Git-клоны одного репозитория. Для второй машины/среды клонируйте `https://github.com/alexisinwork/books.git` в новую папку. Перед началом работы получайте изменения; после редактуры коммитьте согласованный текст, реестры и отчёты вместе и отправляйте их в GitHub.

Если текст правится в Windows Word, откройте файл из выбранной рабочей копии или явно перенесите завершённую редакцию в неё. Затем сравните с прежней версией и обновите запись в `book.json` и зависимости. Две несинхронизированные папки с одинаковым названием не определяют автоматически, какая редакция главнее.

Для DOCX с одновременными изменениями сохраните обе версии и сведите правки явно. История Git позволяет хранить исходные бинарные файлы; текстовые выгрузки и журнал делают содержание изменений обозримым.

По рабочему порядку автора файлы «Было — стало», журналы, вопросы и отчёты хранятся в GitHub. Рабочая или финальная читательская версия каждого романа дополнительно экспортируется в DOCX на `C:\Users\alexi\Desktop`; список вопросов копируется туда в Markdown. Эти настольные файлы предназначены для чтения и ответов. Возвращённый автором DOCX или Markdown нужно явно импортировать, сравнить с репозиторием и только затем назначать новым мастером или основанием правки.

## Подключение проверяющих инструментов

Инструменты устанавливаются как зависимости и программы. В Git храните свои скрипты, конфигурацию, словари, зафиксированные версии зависимостей и результаты запусков. Виртуальные окружения, установленный Java-сервер, бинарники и кэши остаются локальными.

Порядок: выбрать файл по манифесту → проверить SHA-256 → сделать отдельную выгрузку → выполнить проверки → сохранить отчёты → разобрать замечания → внести порученные правки и синхронизировать зависимости.

Инструкции доступны в каждой самостоятельной папке: [default](default/guides/REPOSITORIES.md), [buro](buro/guides/REPOSITORIES.md), [kontakt](kontakt/guides/REPOSITORIES.md), [riokka](riokka/guides/REPOSITORIES.md). Исходный код внешнего проекта нужен отдельным клоном или submodule только при разработке самого инструмента; установка пакета или CLI достаточна для использования готовых функций.

Текущий [GitHub Actions workflow](.github/workflows/validate.yml) запускает тесты рабочих инструментов и `doctor`. Дополнительные языковые проверки подключаются отдельной задачей после установки и настройки инструментов; их результаты должны указывать проверенную версию текста. Наличие зелёного `doctor` не подтверждает прохождение LanguageTool, Vale или литературного аудита.

## Независимые отчёты моделей

Ансамблевый прогон хранится внутри выбранной книги в `audit/ensemble/RUN_ID/` и всегда указывает путь и SHA-256 прочитанного текста. Отчёты ChatGPT/Codex, Claude Code и Gemini являются наблюдениями о конкретной версии. Они не меняют мастер, канон или статус редакторского предложения сами по себе.

Общий `issue-ledger.json` создаётся только после фиксации трёх независимых отчётов. Совпадение нескольких моделей повышает основание для проверки, но не доказывает ошибку; расхождение сохраняется вместе с аргументами. Решение автора, применение к тексту и последующая проверка имеют отдельные статусы. Полный порядок и команды описаны в [EDITORIAL-ENSEMBLE.md](EDITORIAL-ENSEMBLE.md).

## Доступ и внешние копии

На 12 сентября 2026 года этот репозиторий публичный. Для хранения неопубликованных рукописей рекомендуется приватный доступ; изменение видимости выполняется по поручению владельца.

Google Drive и папки доставки могут хранить копии или читательские выпуски. Их состояние описывается отдельно; копирование файла в облако само по себе не меняет основной текст книги. Текущее размещение — [DELIVERY-STATUS.json](DELIVERY-STATUS.json), инструкция по Git — [CREATE-REPOSITORY.md](CREATE-REPOSITORY.md).
