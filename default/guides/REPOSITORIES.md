# Репозитории и инструменты

Подборка проверялась 12 сентября 2026 года по страницам проектов. Базовый комплект работает на стандартной библиотеке Python. Установка всех инструментов сразу не нужна.

| Инструмент | Когда полезен | Практический предел |
|---|---|---|
| [python-docx](https://github.com/python-openxml/python-docx) | Извлечение и сборка Word-документов | Проверка вёрстки остаётся отдельной задачей |
| [Pandoc](https://github.com/jgm/pandoc) | Конвертация текстовых форматов и подготовка сборок | Круговой DOCX → MD → DOCX не гарантирует сохранения оформления |
| [LanguageTool](https://github.com/languagetool-org/languagetool) | Грамматика, пунктуация и стилевые сигналы; русский поддерживается, доступен локальный сервер | Диалог, просторечие и намеренные обрывы требуют авторского решения; мотивация и канон проверяются отдельно |
| [Razdel](https://github.com/natasha/razdel) | Более аккуратное разбиение русского текста на слова и предложения | Не оценивает драматургию и голос |
| [pymorphy3](https://github.com/no-plagiarism/pymorphy3) | Поиск повторов по начальным формам слов | Омонимия и контекст требуют проверки |
| [Vale](https://github.com/vale-cli/vale) | Собственный словарь имён, терминов и редакторских сигналов | Правила надо настроить под книгу; не превращать сигналы в автозамены |
| [rclone](https://github.com/rclone/rclone) | Повторяемое копирование файлов в облако | Настраивать после ручной проверки структуры и прав доступа |

Я бы начал с текущего инструмента snapshots и истории Git, затем подключил LanguageTool для отдельного корректурного прохода. Razdel и pymorphy3 нужны, если вы регулярно исследуете лексику больших рукописей. Pandoc и python-docx — когда появится повторяемая сборка изданий. Vale — когда накопятся собственные устойчивые правила.

Упомянутый в исходном авторском скилле best-seller-studio не включён в зависимости: доступность страницы и содержимое в этой проверке подтвердить не удалось. Оценки литературного качества из внешних фреймворков не принимаются за объективный стандарт.

Сторонний код этих проектов не включён в рабочие зависимости. Здесь ссылки и варианты применения, поэтому не требуется превращать авторский проект в сборку всех чужих репозиториев.

## Как подключить к книжному проекту

Готовые инструменты подключаются через пакеты, CLI и локальный HTTP API. В `integrations/` храните конфигурацию и зафиксированные версии; отчёты — рядом с конкретной проверенной редакцией. Клонировать исходники инструмента внутрь рукописи для его использования не требуется. Submodule имеет смысл при разработке своей версии внешнего инструмента; сам по себе он не запускает проверку.

### Python: Razdel, pymorphy3 и python-docx

Из папки выбранного проекта создайте отдельное окружение и установите библиотеки. Эти команды приведены для выполнения при подключении; они не были запущены при добавлении данного руководства.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install razdel pymorphy3 python-docx
.venv/bin/python -m pip freeze > integrations/check-tools.lock.txt
```

Повторная установка в новом окружении использует `python -m pip install -r integrations/check-tools.lock.txt`. Файл lock включается в Git после фактической установки; `.venv/` исключён через `.gitignore`. [Установка Razdel](https://github.com/natasha/razdel#installation), [pymorphy3](https://github.com/no-plagiarism/pymorphy3), [установка python-docx](https://python-docx.readthedocs.io/en/latest/user/install.html).

Razdel даёт границы предложений/токенов, pymorphy3 — варианты морфологического разбора. Скрипт проверки должен сохранять исходное написание, контекст и адрес места; выбор первой словарной формы не доказывает, что повтор или имя ошибочны. python-docx используется для чтения и контролируемых изменений DOCX; отдельная проверка итогового Word остаётся обязательной.

### Pandoc: отдельная текстовая выгрузка

Установите выбранную версию по [официальной инструкции](https://pandoc.org/installing.html). Перед запуском выберите источник по `book.json`: мастер либо явно указанную рабочую редакцию. Ниже замените `BOOK_ID`, `REVISION` и `RUN_ID` на реальные значения; каталог прогона должен быть новым.

```sh
book_check_source='books/BOOK_ID/revisions/REVISION/revised.docx'
book_check_dir='books/BOOK_ID/revisions/REVISION/checks/RUN_ID'
mkdir -p "$book_check_dir"
pandoc "$book_check_source" --to=plain --wrap=none --output="$book_check_dir/input.txt"
sha256sum "$book_check_source" "$book_check_dir/input.txt" > "$book_check_dir/input-sha256.txt"
pandoc --version > "$book_check_dir/pandoc-version.txt"
```

Сопоставьте выгрузку с Word и сохраните привязку к главам/абзацам. Для выбранного мастера уже есть `tools/studio.py snapshot`; он хранит якоря. Выгрузка отдельной редакции хранится отдельно от `derived/` прежнего мастера. [Pandoc описывает возможную потерю деталей при конвертации](https://pandoc.org/MANUAL.html#description).

### Vale: собственные правила

Установите CLI по [официальной инструкции](https://docs.vale.sh/topics/installation). Для каждого проекта заведите `integrations/vale/.vale.ini` и YAML-правила рядом. Например, конфигурация для собственных правил по обычному тексту:

```ini
StylesPath = styles
MinAlertLevel = suggestion

[*.txt]
BasedOnStyles = Book
```

В `integrations/vale/styles/Book/DraftMarkers.yml` можно начать с сигнала о технических пометках:

```yaml
extends: existence
message: "Проверьте служебную пометку '%s' в читательском тексте."
level: warning
tokens:
  - TODO
  - FIXME
  - UNRESOLVED
```

Это пример настройки, а не установленный набор правил. Имена и термины добавляйте из принятого канона, с учётом контекста и склонения. [Устройство правил](https://docs.vale.sh/checks/existence), [параметры CLI](https://docs.vale.sh/topics/cli).

После создания конфигурации и подготовки выгрузки:

```sh
vale --config=integrations/vale/.vale.ini --output=JSON "$book_check_dir/input.txt" > "$book_check_dir/vale.json"
vale --version > "$book_check_dir/vale-version.txt"
```

Сохраните также код завершения и ошибки запуска; наличие пустого файла отчёта не подтверждает успешную проверку. Англоязычные стилевые наборы нельзя автоматически считать правилами русской художественной прозы.

### LanguageTool: локальный сервер

Скачайте сборку с [официальной страницы локального сервера](https://dev.languagetool.org/http-server), запишите её версию/хеш и установите подходящую Java. В распакованной папке подготовьте `server.properties` (допускается пустой) и запустите:

```sh
java -cp languagetool-server.jar org.languagetool.server.HTTPServer --config server.properties --port 8081
```

В другом терминале, из папки проекта, снова задайте `book_check_dir` тем же путём к каталогу прогона. Подготовьте в нём `chapter.txt` для конкретной главы и запишите его хеш. Запрос с русским языком идёт локальной программе:

```sh
curl --fail-with-body --silent --show-error \
  --data-urlencode 'language=ru' \
  --data-urlencode "text@$book_check_dir/chapter.txt" \
  http://localhost:8081/v2/check \
  --output "$book_check_dir/languagetool.json"
```

Проверяйте главы/фрагменты с учётом лимитов выбранной сборки, сохраняя адреса исходных мест и успешность каждого запроса. Локальный сервер предоставляет базовые правила; облачные AI-правила в него не входят. [Описание сервера и HTTP-вызова](https://dev.languagetool.org/http-server).

## Как результаты становятся частью работы

На каждый прогон сохраняйте исходный путь и SHA-256, хеш выгрузки, версии инструментов и конфигурации, команды, охват, коды завершения и отчёты. Для мастера подходят `audit/checks/RUN_ID/` внутри книги; для отдельного варианта — `revisions/REVISION/checks/RUN_ID/`.

Сигналы разбираются вручную. Принятые замечания получают запись в `audit/issues.json`; после применения обновляются текст, журнал и зависимые состояния по [SCENE-EDITING.md](SCENE-EDITING.md). Подключение автоматизации к GitHub Actions — отдельная настройка: установить зафиксированные версии, выбрать входной файл и сохранить отчёты. Нынешний `doctor` не запускает эти внешние программы.

Для первой интеграции достаточно одного языкового прохода LanguageTool по выбранной версии и её журналу. Vale добавляется для собственных повторяющихся правил; Razdel и pymorphy3 — для анализа лексики и границ текста. Мотивы персонажа, канон и арифметику событий проверяйте отдельным проходом.
