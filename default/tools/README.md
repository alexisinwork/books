# Локальные инструменты

Python 3.10+, только стандартная библиотека. Для команд книги работайте из папки соответствующей серии либо укажите её через --root. `python tools/studio.py --help` показывает все параметры.

| Команда | Результат |
|---|---|
| new-project | Самостоятельная копия чистого default; новые project_id/workspace_uid, пустые книги, сброшенные внешние ссылки |
| new-book | Чистая папка тома, свои ID, собственная копия профиля, пустой master |
| set-master | Явный выбор существующего файла внутри книги, проверка формата, хеш и журнал |
| snapshot | Извлечение тела текста и якорей, текстовая проекция для сравнения |
| compare-voices | Различия настроек двух книг без оценки качества |
| context | Стартовые материалы одной книги и указатели на следующие источники |
| doctor | Согласованность project/book/profile ID, путей, формата DOCX и хешей выбранных версий |

new-project принимает --out как путь новой папки и --root как путь чистого default. Он не копирует существующие books, внешние подключения и контрольную сумму прежней поставки. Исторический документ переносится как явно обозначенный источник методики. Книги и активный канон остаются пустыми. Две независимые копии получают разные workspace_uid, а совпадение project_id у соседних папок запрещено.

new-book не заменяет существующую книгу; копия пресета независима от последующих изменений profiles. Если запись манифеста не удалась, созданная папка откатывается. Запускайте одну изменяющую команду на проект за раз.

Пути мастера задаются относительно папки книги. Для не подтверждённого автором кандидата snapshot/context требуют явное --allow-candidate. Это разрешает инвентаризацию, но не превращает файл в окончательный. После правки мастер меняет хеш: выполните set-master с причиной новой редакции, затем snapshot. Старые цитаты и end-state перепривязываются отдельно.

Для DOCX с отслеживаемыми исправлениями, текстовыми блоками или особым порядком чтения reader останавливается либо сообщает об исключённых частях. Потребуется дополнительная проверка исходника. Текстовый файл с расширением .docx нельзя молча считать Word-документом.

`prepare_repository.py` переносит четыре готовые папки default, buro, kontakt, riokka в новую общую папку, копируя их файлы без изменения текста. Он не создаёт удалённый репозиторий. Пример — в guides/DRIVE-AND-GITHUB.md.

`verify_package.py` проверяет перечисленные в манифесте файлы. По умолчанию это CHECKSUMS.json из соответствующего проекта; можно указать --root и --manifest. Отсутствующий манифест или несовпадение хеша — явный результат, а не повод переписать файл. После собственных изменений снимок поставки закономерно устаревает. Исходный документ системы проверяется отдельно через --manifest methods/history/source-manifest.json.

doctor не обнаруживает все сюжетные ошибки, не проверяет вёрстку и не заменяет языковой редактор. JSON-формы не являются исполняемыми правилами арифметики. Тесты защищают версии, чистое создание проекта и книги, изоляцию контекста, полный перенос четырёх папок и отказ от перезаписи:

```sh
python -m unittest discover -s tests -v
python tools/studio.py doctor
```
